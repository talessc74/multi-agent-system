# _local-edr-policy-017: agent-creator internal identifier sanitization

## Context and Problem Statement

The project status (Notion) recorded a known bug: the internal name "Auditor
Kern 0xF1" (the creator system's own identity, from ESPECIALISTA_V2) leaking
into generated legal agents in Modes 2 and 4 — the two modes that create
"advogado" agents on demand via `createAgentFromScratch` when none exists yet
in the registry or Firestore shelf.

`_local-edr-policy-010` (specificJudge null-sentinel filtering) explicitly
flagged this as a different, unaddressed mechanism: "prompt-instructed field
omission, not a type-system sentinel — needs its own review."

Root cause, confirmed by reading the code: `ESPECIALISTA_V2`'s system
instruction tells Gemini "NUNCA cite o legado original... nunca inclua campos
'kernel' ou identificadores internos do sistema criador" — but this is prose
only. Nothing in `generateAgent()` validates or filters the response before
it is returned. `agent-resolver.ts`'s `createAndSaveAgent` then persists the
raw result directly to Firestore (`conteudo: result.agente`) with no
sanitization step, so a leak, once it happens, is permanent for that cached
agent until someone finds and fixes it manually.

## Decision Outcome

**Add a code-level sanitization pass inside `generateAgent()`, the single
choke point every generated agent passes through, before the result is
returned to any caller.**

### Details

- New module `agent-sanitizer.ts` exports `sanitizeGeneratedAgent(agente)`,
  which recursively walks the parsed agent object:
  - Drops any key literally named `kernel` (case-insensitive) at any depth.
  - Redacts any string value matching `/auditor\s*kern/i`, `/0xf1/i`,
    `/shaw_auditor_kern/i`, or `/arquiteto especialista/i` (the creator
    system's own display name) — replaced with a `[REDIGIDO: ...]` marker.
  - Returns both the cleaned object and a `leaksFound` list of what was
    removed, for the caller to log.
- `generateAgent()` calls this on `parsed.agente` immediately after
  `safeParseJSON`, before returning. If `leaksFound` is non-empty, it
  `console.warn`s with the agent id and the list — observable in Cloud Run
  logs — but does not fail agent creation.
- The `Arquiteto Especialista` pattern is deliberately the specific phrase
  (not the bare word "especialista", which is common legitimate legal
  vocabulary — e.g. "advogado especialista em Direito do Consumidor").
  Verified by test that this does not false-positive.
- Does **not** modify anything inside the "PRATA DA CASA" block
  (`SHAW_V2`/`ESPECIALISTA_V2`) or the creation instructions given to Shaw
  V2, which `_local-edr-policy-008` already formalizes as correct. This is
  strictly an added output-validation layer, defense-in-depth for a prompt
  instruction that is necessary but not sufficient.
- 7 tests in `__tests__/agent-sanitizer.test.ts` cover: nested `kernel`
  field, `Auditor Kern 0xF1` in a string, bare `0xF1`, `Arquiteto
  Especialista` without false-positiving on "advogado especialista",
  idempotency on an already-clean agent, array/object nesting, and
  `null`/`undefined` input.

## Relationship to other policies

- Closes the gap `_local-edr-policy-010` explicitly left open ("needs its
  own review").
- Does not change anything `_local-edr-policy-008` (Demand-Driven Agent
  Creation) governs — creation still only happens in `resolveAgent`'s
  Camada 3, on real demand; this policy only changes what happens to the
  output before it is returned/persisted.
