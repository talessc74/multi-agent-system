# _local-bdr-policy-003: Judge Location Anonymization

## Context and Problem Statement

When a specific judge is identified during case validation, the system can use Shaw V2
to create a legacy seed based on that judge's intellectual profile. The comarca (geographic
jurisdiction) may be known at creation time.

Small comarcas in Brazil often have a single sitting judge. If the comarca name is stored
in agent seeds, Firestore documents, or any persistent artifact, an audit of the system's
files could link the agent's intellectual profile directly to a real, identifiable person.
This creates a juridical risk: the simulation could be seen as attributing specific legal
positions to a real magistrate, with potential professional or legal consequences.

## Decision Outcome

**Comarca and geographic location information must never be stored in any persistent
artifact related to judge agents.**

This is a non-negotiable product rule. The risk of identifiability in small comarcas
outweighs the benefit of location-specific caching.

### Rules

#### What is prohibited

- Storing `comarca` or any geographic identifier in a judge's Firestore document.
- Including comarca or city/state in the seed generated by Shaw V2 for a judge.
- Referencing a specific judge's real location in the description passed to Shaw.

#### What is permitted

- Shaw MAY receive a judge's name to identify their intellectual reference profile.
  Shaw's PROTOCOL_ANON will anonymize the source in the seed output — the person's
  name must never appear in the JSON seed.
- The `comarca` parameter may be used transiently at runtime for routing decisions
  (e.g., selecting a previously created area-specific agent) but must not be written
  to Firestore or any stored file.

#### Implementation requirements (agent-resolver.ts, agent-creator.ts)

- `agent-resolver.ts`: when saving a judge entry to Firestore, always set
  `comarca: null` — regardless of what `params.comarca` contains.
- `agent-creator.ts`: the description passed to Shaw for `tipo='juiz'` must
  not include geographic location. A specific judge's name may be included
  so Shaw can identify their intellectual profile, but the comarca must be omitted.

```typescript
// agent-creator.ts — correct description for a specific judge:
// DO:   "juiz especializado em direito trabalhista — perfil de Dra. Maria Silva"
// DON'T: "juiz especializado em direito trabalhista da comarca de Dra. Maria Silva"
// DON'T: "juiz da comarca de São João da Barra especializado em..."
```

- Shaw's PROTOCOL_ANON is already active and replaces names with semantic
  identifiers (SOURCE_ID, REGION_ALPHA, etc.) in the seed output. This provides
  a second layer of protection even if a name is inadvertently passed.

#### Relationship to LGPD (EDR-governance-001)

LGPD anonymization (EDR-001) covers user-submitted case data. This policy (BDR-003)
covers internal system artifacts (seeds, Firestore agent documents). Both must be
respected independently.

## Rationale

A comarca with a single sitting judge has zero anonymity by location. Storing
"comarca: Pequenópolis" in a Firestore document that also contains an intellectual
profile derived from that judge's known legal positions is equivalent to storing a
behavioral profile of a real, identifiable person — without their consent, and without
any legitimate legal basis under LGPD Art. 7.

The system's value is in the quality of legal simulation, not in geographic precision
of agent sourcing. Accepting a generic regional agent rather than a location-specific
one is the correct trade-off.
